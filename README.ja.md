# WiseTrack · スマートフォン・視聴画面版

[English](README.md) · [Türkçe](README.tr.md) · [Español](README.es.md) · [العربية](README.ar.md) · [Русский](README.ru.md) · [中文](README.zh.md) · **日本語** · [한국어](README.ko.md)

WiseTrack は、ブラウザーで動作するげっ歯類の行動追跡ソフトウェアです。このフォルダーは、スマートフォン上でアプリのように動作するウェブ版（PWA）です。同じファイルが iPhone、Android、タブレット、パソコンで動作します。

| ファイル | 役割 |
|---|---|
| `index.html` | 追跡を行うアプリ（スマートフォンで開く） |
| `izle.html` | 視聴画面：パソコン、テレビのブラウザー、タブレットで開き、スマートフォンの映像と結果をリアルタイムで表示 |
| `sw.js`、`*.webmanifest`、`icons/` | アプリとしてのインストールとオフライン動作 |
| `vendor/` | ミラーリング（PeerJS、MIT）と QR コード（qrcode-generator、MIT）のライブラリー |
| `i18n/` | インターフェースの翻訳（英語、スペイン語、アラビア語、ロシア語、中国語、日本語、韓国語） |

**対応するインターフェース言語：** Türkçe、English、Español、العربية、Русский、中文、日本語、한국어。言語は上部バーのメニューから選びます。詳しくは[インターフェース言語](#インターフェース言語)を参照してください。

## 1. 公開（1回のみ、約5分）

スマートフォンのブラウザーは **https://** のアドレスでしかカメラを開けません。ファイルをスマートフォンに直接コピーしても動作しないため、無料の https アドレスに置く必要があります。

**GitHub Pages（推奨、恒久的かつ無料）**
1. github.com で無料アカウントを作成し、**New repository** で*公開*リポジトリ（例：`wisetrack`）を作ります。
2. **Add file → Upload files** でこのフォルダーの*中身*（index.html が最上位になるように）をドラッグし、**Commit** します。
3. **Settings → Pages → Branch: main / (root) → Save**。1〜2分後、アドレスは `https://ユーザー名.github.io/wisetrack/` になります。

代替手段：フォルダーを Netlify Drop（app.netlify.com/drop）にドラッグ＆ドロップしても https アドレスが得られます。恒久的に使うには無料アカウントで登録する必要があります。

更新するときはファイルを再アップロードし、`sw.js` の `VERSION` の値を上げてください（例：`wisetrack-v13` から `wisetrack-v14` へ）。スマートフォンは次にアプリを開いたときに新しいバージョンを取得します。

## 2. スマートフォンへのインストール

- **iPhone / iPad：** **Safari** でアドレスを開く → 共有アイコン → **ホーム画面に追加**。初回起動時にカメラへのアクセスを許可します。
- **Android：** **Chrome** でアドレスを開く → メニュー（⋮）→ **アプリをインストール**（または「ホーム画面に追加」）。

インストール後は、追跡はインターネットなしで動作します。ミラーリングにはインターネットが必要です。

## 3. 追跡のためのスマートフォンの配置

- 三脚やホルダーでスマートフォンをアリーナの**真上**に固定します。実験中に動いたり回転したりしてはいけません。
- **メイン（1×）の背面カメラ**を使ってください。超広角（0.5×）レンズや広角ウェブカメラは縁を曲げて写します。この歪みは下記の**アリーナからレンズの歪みを測定**で補正できますが、メインカメラの映像がやはり最もきれいです。
- 照明を調整したら**露出とフォーカスを固定**をタップします（Android で動作します。iPhone のブラウザーでは許可されないため、安定した均一な照明を使ってください）。
- 長時間のセッションではスマートフォンを充電しておきます。アプリが開いている間は画面が消えません。アプリを離れると、安全のためセッションは一時停止します。

### 自動キャリブレーションとカメラ補正

設定 > 試験装置とキャリブレーション にて：

- **アリーナを自動検出**：アリーナが空のときにタップします。アプリは画像の中央から床を切り分け、アリーナの既知の形（正方形、円、十字）をサブピクセル精度で縁に合わせて点を配置します。円形のアリーナ（水迷路、バーンズ）では、カメラが傾いていると円の中心は楕円の中心に写りません。アプリはカメラの幾何から中心を計算します。十字迷路では、クローズドアームを壁から認識します。確信が持てない場合は**アームを入れ替え**で修正してください。壁が床と同じ色の場合、点が壁の上端に合わせられることがあります。アプリはそれを検出すると警告します。
- **キャリブレーションを確認**：画像上のアリーナの縁がモデルから平均何 cm ずれているかを表示します（0.5 cm 以下なら良好、1.5 cm を超える場合は点を確認）。この値は各試行の開始時にも自動で測定され、Excel/CSV の概要に書き込まれます。
- **動物の高さの補正**（「カメラ・レンズ・動物の高さ」の項目）：カメラが捉えるのは動物の背中であり、床上の位置ではありません。カメラの高さと位置をアリーナの点から推定し（実測した場合は高さを入力）、追跡点を床面に投影します。補正しないと、カメラが真上にあっても縁付近の位置が外側にずれ、総移動距離がおよそ 動物の高さ /（カメラの高さ − 動物の高さ）だけ過大になります（ラット、カメラ高 75 cm：約 5.6%）。
- **アリーナからレンズの歪みを測定**：チェッカーボードは不要です。アリーナの直線の縁がまっすぐに（円形アリーナでは縁が楕円に）なる歪み係数を求めます。
- **カメラのずれを監視**（既定でオン）：試行中にカメラやスマートフォンがぶつかってずれた場合、アリーナの縁を毎秒最初のフレームと比較します。ずれが見つかると、点と空のアリーナの基準を一緒に移動し、その出来事を概要に記録します。
- 動物の見かけの大きさがアリーナの端から端で明らかに変わる場合（カメラの傾きや点のずれ）、結果に警告が表示されます。

合成動画による検証（カメラ位置、レンズの歪み、ラットの大きさが既知、追跡点の高さ 4 cm）：カメラが 18° 傾き、歪みがはっきりある条件では、点を手で正確に置いても補正なしの位置誤差は中央値 1.3 cm、95 パーセンタイル 3.1 cm で、移動距離は 9.8% 過大でした。自動キャリブレーション＋レンズ＋高さの補正では、誤差は中央値 0.16 cm、95 パーセンタイル 0.8 cm、移動距離の差は 0.2% でした。80° の広角カメラでは 1.9 → 0.2 cm、水迷路（カメラ高 220 cm）では 0.34 → 0.26 cm、バーンズ迷路では 1.6 → 0.2 cm。試行の途中でカメラが 2 cm ずれた場合、誤差の中央値は補正なしで 1.7 cm、ずれの監視ありで 0.15 cm でした。

## 4. 別の画面へのミラーリング

**アプリ独自のミラーリング（どの機器でも動作）：** スマートフォンで **ミラーリング → ミラーリングを開始** を選びます。表示された QR コードをタブレットのカメラで読み取るか、パソコンやテレビのブラウザーで `…/izle.html` を開いて6文字のコードを入力します。ラベル付きのライブ映像、時間、ゾーン表、移動距離がそこに表示されます。「視聴画面から開始/停止できるようにする」がオンなら、アリーナに近づかずにそこから試行を操作できます。コードはスマートフォンに保存されます。テレビで視聴ページを一度ブックマークしておけば、以後の実験でも同じコードで接続します。複数の画面を同時に接続できます。

仕組み：2台の機器は無料の PeerJS サーバーを介して互いを見つけるだけで、映像とデータは機器間で直接（WebRTC、暗号化）やり取りされます。施設のネットワークが機器間の接続を遮断する場合は、スマートフォンのテザリング（インターネット共有）をオンにして、視聴機器をそこに接続してください。

## 5. 結果の書き出し

「結果」タブの **Excel (.xlsx)** では、1つのファイルに4つのシートが出力されます：*概要*（指標と使用した設定）、*ゾーン*、*位置記録*（フレームごとの X/Y、速度、ゾーン）、*1行*（動物ごとに1行の結果。グループの表にそのまま貼り付けられます）。CSV と PNG の選択肢もあります。スマートフォンでは書き出すと共有メニューが開き、Drive、ファイル、メールなどを選べます。

## 6. 新奇物体認識（NOR）

設定 > 試験装置 で**物体認識**を選び、段階（馴化 / 馴致 / テスト）を設定します。物体がアリーナにあり動物がいない状態で**物体を自動検出**をタップすると、物体が検出され、同じフレームが空のアリーナの基準として保存されます（これにより物体が動物と誤認されるのを防ぎます）。検出された物体は、画像上でドラッグして移動したり、白い四角のハンドルで大きさを変えたり、形（円/長方形）を変えたり、削除したり、手動で追加したりできます。テスト段階では、どれが新奇物体かを選ぶまで記録は始まりません。

既定では、動物の**鼻先点**が物体から 2 cm 未満にあるときに探索として数えます。体の中心が物体の上にある場合（登っている場合）は探索として数えません。鼻先点は体の形（頭側が細い）と移動方向から推定され、画面上では水色の点で表示されます。結果には物体ごとの探索時間、探索回数、初回探索潜時が示され、テスト段階では弁別指数 DI =（新奇 − 既知）/（新奇 + 既知）と認識指数 RI が示されます。鼻先の推定は、手作業で採点した数本の動画と比較して検証してください。必要なら基準を「中心点」に切り替えられます。

**動物と同じ色の物体。** 物体そのものが動物と誤認されないよう、アプリは3つの対策をとります。(1) ライブカメラで「アリーナで動物を検出したら開始」がオンのとき、開始を押すと空のアリーナ（物体が最終位置にある状態）が自動で保存し直されます。その間、画面には「空のアリーナを保存中です。まだ動物を入れないでください」と表示されます。(2) 続いて各物体を確認します。空のアリーナの基準があるにもかかわらず動物のように見える物体（例えば基準の保存後に動かされた場合や、動画に基準がない場合）は、その試行で動物の検出から除外され、警告が表示され、Excel の概要に記録されます。(3) 完全に物体の上にある塊は、動物が直前までそこにいた場合（登っている場合）を除き、動物として選ばれることはありません。除外された物体では登る行動を判別できず、物体から 0.5 cm 以内の鼻先は見えません。そのため探索時間がやや低めに出ることがあります。設定の「物体の領域を常に動物の検出から除外」を選ぶと、すべての試行で同じ除外が適用されます。

## 7. モリス水迷路（MWM）

設定 > 試験装置 で**水迷路**を選び、プールとプラットフォームの直径を入力し、段階（訓練 / プローブテスト / 可視）とスタート地点を選びます。画像上の北・東・南・西の点を、プールの縁にある各方位の印へドラッグします。画像上でプラットフォームを実際の位置へドラッグします。目標象限と反対象限はプラットフォームの位置から自動で決まります。動物がいないときに 検出 > **空のアリーナを保存** で空のプールを保存してください。これで水面の一定の光の反射が動物と誤認されなくなります。水迷路を選ぶと試行時間は 60 秒に設定されます。

- **訓練と可視プラットフォーム：** 動物の中心点がプラットフォームの範囲に入り、設定時間（既定 2 秒）とどまると試行は自動で終了します。逃避潜時（プラットフォームへの初回到達）、プラットフォームを見つけたかどうか、経路長、経路効率（スタートからプラットフォームまでの直線距離 / 泳いだ距離）、目標象限での滞在時間、プラットフォームまでの平均距離、壁際での滞在時間（接触走性）、遊泳速度が示されます。時間内にプラットフォームが見つからなかった場合、逃避潜時は試行時間として記録されます。
- **プローブテスト：** 目標象限と反対象限での滞在時間の割合、プラットフォーム位置の通過回数、プラットフォーム位置への初回到達時間、プラットフォームまでの平均距離が示されます。プラットフォーム位置の通過にはゾーン移行時間は適用されません。

Excel ファイルの*1行*シートでは、「目標象限」と「反対象限」の列名はどの動物でも同じなので、グループ間でプラットフォームの位置が異なっても結果を上下に貼り付けられます。

## 8. バーンズ迷路

設定 > 試験装置 で**バーンズ迷路**を選び、プラットフォームの直径、穴の数、穴の直径、穴の中心からプラットフォームの縁までの距離を入力します（マウス用プラットフォームの既定値：92 cm、20 穴、5 cm）。北・東・南・西の点をプラットフォームの縁へドラッグします。**北の点は1番の穴に揃える必要があり**、穴は時計回りに番号が付きます。描かれた穴のリングが画像の穴と合わない場合は、**穴を自動で合わせる**をタップするか、スライダーで回転させます。目標（逃避）の穴はリストから選ぶか、画像上の穴をタップして指定します。動物がいないときに 検出 > **空のアリーナを保存** で空のプラットフォームを保存してください。そうしないと、暗い穴（特に黒い動物の場合）が動物と誤認されることがあります。バーンズを選ぶと試行時間は 180 秒に設定されます。

- **穴への訪問：** 動物の鼻先点が穴の縁から 1 cm 以内（調整可）に近づくと訪問として数えます。目標以外の穴への訪問はすべてエラーで、同じ穴への繰り返しの訪問も数えます。
- **訓練：** 一次潜時、一次エラー、一次経路（目標の穴への初回訪問まで）と、総潜時、総エラー、総経路（動物が逃避箱に入るまで）が示されます。動物が目標の穴のそばで 1 秒間（調整可）画像から消えると逃避箱に入ったとみなされ、試行が終了します。消えた時点が総潜時です。
- **プローブテスト：** 目標の穴と他の穴への訪問回数、目標の穴の訪問割合、目標象限での滞在時間、一次の各指標が示されます。
- **探索戦略**は自動で提案されます：*直接*（エラー3回以下で、すべて目標から2穴以内）、*系列*（一方向に連続して隣接する穴を3つ以上）、その他は*ランダム*。穴の訪問順は Excel の概要に書き込まれます。提案はこの順序で確認してください。

Excel ファイルの*1行*シートでは、穴の列は「穴 1 … 穴 N」、象限の列は「目標象限」「反対象限」と2つの隣接象限と名付けられるため、目標の穴が動物ごとに変わっても結果を上下に貼り付けられます。

## 9. MPG、AVI などの動画形式

ブラウザーは MP4（H.264）、MOV、WebM の動画を直接開けます。MPG/MPEG（MPEG-1/2）、VOB、AVI、WMV、FLV、TS/MTS などの形式を選ぶと、アプリは **MP4 に変換して開く** ボタンを表示します。変換は ffmpeg.wasm によって完全に端末上で行われ、動画はどこにも送信されません。変換ツール（約 32 MB）は初回使用時に jsDelivr からダウンロードされ、ブラウザーのキャッシュに残るため、初回の変換にはインターネットが必要です。インターレースの DVR/DVD 録画は自動でインターレース解除され、画像は最大 960 ピクセル幅に縮小されます。パソコンでは1分間の標準画質の動画が約30秒で変換されます。スマートフォンではより時間がかかります。変換後のファイルを**変換した動画を保存**で保存しておけば、同じ動画を再解析するときに再変換は不要です。

ffmpeg.wasm（@ffmpeg/core 0.12.10）は GPL-2.0-or-later ライセンスです。アプリは実行時に CDN から読み込むだけです。ソースコード：https://github.com/ffmpegwasm/ffmpeg.wasm

### 解析速度

動画を解析するとき、速度の選択は上限です。ブラウザーが1秒間に渡せるフレーム数は画面のリフレッシュレート（通常 60）までで、負荷の高い端末ではフレームを取りこぼすこともあるため、アプリはすべてのフレームを処理できるよう速度を自分で調整します。取りこぼしがない間は速くし、取りこぼした時点で遅くします。解析が終わると平均速度とスキップしたフレームの割合が表示され、Excel/CSV の概要にも書き込まれます。割合が 1% を超える場合は、速度の上限を下げて解析をやり直してください。平滑化はフレーム数ではなく時間で行われるため、同じ動画はどの速度で解析しても同じ結果になります。

### 動画の一括解析

「設定」タブの最後にある **5 · 動画の一括解析** カードは、同じ装置で撮影した動画を順番に解析します：

1. **動画を追加**で複数の動画を選びます（パソコンではカードの上にドラッグ＆ドロップすることもできます）。リストはファイル名順に並びます。動物コードはファイル名から取られ、表で変更できます。物体認識では新奇物体を、水迷路ではスタート地点を、行ごとに個別に選べます。
2. **設定用に最初の動画を開く**で、アリーナ（物体認識では物体も）、しきい値、時間を一度設定します。
3. オプション：**アリーナの配置**はすべての動画で同じにすることも、動画ごとに自動検出することもできます（動画の間でカメラが動いた場合）。**空のアリーナの基準**は既定では各動画から抽出されます。動画全体に分散した 21 フレームでは、動物は各地点に少数のフレームでしか写らないため、各ピクセルの 30 パーセンタイル（アルビノ動物）または 70 パーセンタイル（暗い色の動物）が動物のいない床になります。
4. **一括解析を開始**。MPG/AVI などの形式は順番が来ると自動で変換されます。開けない動画や動物が見つからない動画には印が付けられて飛ばされ、解析は止まりません。**停止**で中断したリストは**残りを解析**で続けられます。
5. 終わると、パソコンでは**一括 Excel** ファイルが自動でダウンロードされます（スマートフォンではボタンをタップ）。シート：*一括結果*（動画ごとに1行、単一動画の Excel のすべての指標）、*ゾーン*（ロング形式）、*品質*（検出/スキップしたフレーム、キャリブレーションのずれ、カメラのずれ、警告）、*設定*、および任意で*位置記録*。

解析中はタブを開いたまま前面に表示しておく必要があります。ブラウザーはバックグラウンドのタブに動画フレームを渡さないためです。タブがバックグラウンドに回ると解析は一時停止し、戻ると続きから再開します。画面は自動では消えません。

## 10. オフラインの単一ファイル版（パソコン用）

`wisetrack.html` も別途提供されています。パソコンにダウンロードしてダブルクリックすると Chrome または Edge で開きます。インストール、インターネット、アカウントは不要です。カメラ、動画解析、Excel 書き出し、すべてのインターフェース言語を含め、すべての機能が動作します。この版ではアプリ内ミラーリングのみ無効で、MPG などの形式の変換にはインターネットが必要です。ダウンロードした HTML ファイルはスマートフォンでは確実に開けないため、スマートフォンではウェブアドレスを開いてホーム画面に追加する方法を使ってください。

## 11. 独自のシグナリングサーバー（任意）

公開の PeerJS サーバーに接続できない場合や施設内で完結させたい場合は、ネットワーク上のパソコンで `npx peer --port 9000` を実行し、両方のページを `?ps=サーバーIP:9000` を付けて開きます（https がない場合は `&pss=0` も追加します）。

## 次のステップ：ネイティブアプリ

このコードベースは Capacitor で Android アプリ（APK）と iOS アプリ（Xcode プロジェクト）にパッケージ化される予定です。ネイティブ版では、iPhone での露出/フォーカスの固定、バックグラウンドでの途切れない記録、より高いフレームレートが追加されます。
